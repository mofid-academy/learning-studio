# فعال‌سازی پنل مشترک مفید آکادمی

پنل فعلی و دوره‌های ذخیره‌شدهٔ آن حفظ شده‌اند. قابلیت جدید در مسیر جدا از Gemini کار می‌کند. تا زمانی که راه‌اندازی زیر تکمیل نشده، `enabled` برابر `false` می‌ماند و پنل فعلی همچنان باز می‌شود. این وضعیت، دسترسی شرکت‌کننده‌ها را فعال نمی‌کند.

## ۱. جدول دائمی

در همان پروژهٔ n8n جدید، به **Overview → Data Tables** بروید. جدول `mofid_learning_portal` را با دو ستون **String** بسازید:

| نام ستون | نوع |
|---|---|
| `key` | String |
| `value` | String |

ستون‌های خودکار n8n را حذف نکنید. جدول را روی GitHub قرار ندهید. حساب‌ها، هش رمز، نشست‌ها، دوره‌ها و پیشرفت داخل این جدول هستند.

## ۲. ورک‌فلوی جدید

فایل `Mofid-Portal-n8n.json` را Import کنید. این ورک‌فلو مستقل است؛ جایگزین ورک‌فلوی Gemini نشود.

در نود **Portal API** فقط دو خط ابتدای کد را تنظیم کنید:

```js
const ADMIN_USERNAME = 'admin';
const ADMIN_PASSWORD = 'رمز خصوصی بلند انتخابی شما';
```

رمز سوپرادمین باید حداقل ۱۶ نویسه داشته باشد. رمز واقعی را فقط داخل n8n بگذارید؛ فایل حاوی رمز را در مخزن عمومی، سایت یا این گفت‌وگو ارسال نکنید. دسترسی ویرایش n8n را فقط به مدیران مجاز بدهید.

در دو نود **Load Portal Records** و **Save Portal Record**، جدول همین پروژه را انتخاب کنید. نام پیش‌فرض `mofid_learning_portal` است. در نود ذخیره، شرط باید `key Equals {{ $json.key }}` و دو مقدار ستون باید `{{ $json.key }}` و `{{ $json.value }}` باشد.

نود اول **Portal Webhook**:

- HTTP Method: `POST`
- Path: `mofid-learning-portal`
- Respond: `Using 'Respond to Webhook' Node`
- Allowed Origins (CORS): `https://mofid-academy.github.io`

Save و **Publish** کنید. Production URL پیش‌فرض:

`https://miladmmirsheri.app.n8n.cloud/webhook/mofid-learning-portal`

## ۳. اتصال و آزمون پیش از فعال‌سازی

در سایت فعلی، دکمهٔ **مدیریت دسترسی و انتشار** را بزنید. آدرس وبهوک جدید را بررسی کنید و با حساب سوپرادمین وارد شوید.

1. در تب «انتشار دوره‌ها»، یک دورهٔ موجود را «انتشار برای شرکت‌کننده‌ها» کنید.
2. در تب «حساب شرکت‌کننده‌ها»، نام کاربری، نام شخص، نام سازمان و رمز را وارد کنید. رمز شرکت‌کننده حداقل ۱۲ نویسه است. نام کاربری باید انگلیسی/عدد و حداقل ۳ نویسه باشد.
3. اگر ورود یا ذخیره موفق نشد، `enabled` را فعال نکنید. اجرای همین ورک‌فلو را بررسی کنید؛ خطای ذخیره نباید پیام موفقیت بدهد.

## ۴. فعال‌کردن ورود مشترک

در مخزن `mofid-academy/learning-studio`، فایل **portal-config.json** را باز و ویرایش کنید. فقط `enabled` را از `false` به `true` تغییر دهید و Commit کنید. آدرس API باید Production URL مرحلهٔ قبل باشد. این فایل هیچ رمز یا توکنی ندارد.

بعد از موفق‌شدن انتشار GitHub Pages، سایت را با Ctrl+F5 باز کنید. از این لحظه پنل اصلی هم ورود می‌خواهد:

- سوپرادمین: `https://mofid-academy.github.io/learning-studio/`
- شرکت‌کننده: `https://mofid-academy.github.io/learning-studio/?portal=participant`

شرکت‌کننده حتی اگر لینک اصلی را باز کند فقط پنل یادگیری را می‌بیند. ثبت‌نام عمومی وجود ندارد. آدرس مخصوص شرکت‌کننده را همراه نام کاربری و رمز به او بدهید.

برای آزمون نهایی از مرورگر یا پنجرهٔ ناشناس جدا استفاده کنید: ورود شرکت‌کننده، دیدن دوره، پاسخ به سؤال، خروج و ورود دوباره. پیشرفت باید باقی بماند. در پنل شما، تب «عملکرد شرکت‌کننده‌ها» نتیجه را نشان می‌دهد. تعداد صحیح در سرور از پاسخ‌ها محاسبه می‌شود.

## رفتار انتشار و حساب‌ها

- ساخت و ویرایش دوره مثل قبل در مرورگر شما انجام می‌شود؛ با دکمهٔ انتشار، نسخهٔ مشترک به سرور منتقل می‌شود. برای تغییرات بعدی انتشار مجدد لازم است.
- پاسخ‌ها و پیشرفت شما در نسخهٔ منتشرشده حذف می‌شود تا حساب‌ها از صفر و مستقل شروع کنند.
- اگر دوره پاسخ ثبت‌شده دارد، محتوای آن را نمی‌توان روی همان شناسه جایگزین کرد. یک نسخهٔ جدید وارد کنید تا شناسهٔ جدید بگیرد، سپس منتشر کنید؛ این کار مانع مخلوط‌شدن پاسخ‌های نسخهٔ قبلی می‌شود.
- حذف محلی دوره از مرورگر، آن را از سرور حذف نمی‌کند. برای بستن دسترسی مشترک، در پنل مدیریت «بستن دسترسی» را بزنید. پاسخ‌ها نگه داشته می‌شوند.
- غیرفعال‌کردن حساب یا تغییر رمز، نشست‌های قبلی آن کاربر را هم نامعتبر می‌کند. نشست ورود ۸ ساعت اعتبار دارد. پنج تلاش ناموفق، ورود همان نام کاربری را تا پایان بازهٔ ۱۵ دقیقه‌ای محدود می‌کند.
- رمز شرکت‌کننده به‌صورت PBKDF2 با salt تصادفی ذخیره می‌شود؛ توکن نشست نیز فقط به‌صورت هش در جدول قرار دارد. هیچ رمز شرکت‌کننده‌ای به مرورگر سایر کاربران برنمی‌گردد.

## ظرفیت و نگهداری

این نسخه برای گروه‌های آموزشی محدود با n8n Data Tables آماده شده است. هر درخواست، رکوردهای جدول را برای پردازش می‌خواند؛ برای تعداد زیاد دوره یا کاربر باید به پایگاه دادهٔ اختصاصی مهاجرت کند. سهم فضای Data Tables تابع پلن n8n است. انتشار هر دوره در این نسخه تا ۸ مگابایت پذیرفته می‌شود؛ محدودیت با پیام روشن اعلام می‌شود. این با سقف فایل ورودی در ابزار ساخت دوره متفاوت است.

از جدول n8n نسخهٔ پشتیبان بگیرید. برای پاک‌سازی نشست‌های قدیمی، فقط رکوردهای `session:` با `expiresAt` گذشته را حذف کنید؛ رکوردهای `user:`، `course:` و `progress:` را حذف نکنید. ورک‌فلو ذخیرهٔ اطلاعات اجرای موفق و ناموفق را غیرفعال می‌کند تا رمز و توکن ورودی در سابقهٔ اجرای آن نگهداری نشوند.

## نتیجهٔ بررسی‌ها

منطق سرور با آزمون ورود، محدودیت نقش، لغو دسترسی، تغییر رمز، جداسازی پیشرفت دو کاربر، جلوگیری از افشای رمز، انتشار و بستن دوره و محاسبهٔ نتیجه بررسی شده است. اجرای واقعی روی حساب n8n شما بعد از Import و ساخت جدول باید تأیید شود؛ دسترسی مستقیم به آن حساب در این نشست فراهم نیست.
